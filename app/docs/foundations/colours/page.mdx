# Colours

Open HR's colour system has two layers: raw values at the primitive level, and context-aware decisions at the token level. No component should ever reference a primitive directly. Primitives exist only to power tokens, and tokens are what the UI uses.

Tokens are mode-aware: the same token points at a different primitive in light and dark mode. There are two kinds: generic tokens for system-wide roles such as surface, border and text, and component tokens where a component needs a value the generic set doesn't cover.

[Open the colours in Figma](https://www.figma.com/design/7jCMwDng7HF5g7F3tGXf0E/Open-HR?node-id=317-21910)

## Using tokens

Token paths map to CSS variables: replace every `/` with `-` and add `--` in front, so `bg/primary` becomes `--bg-primary`. In Tailwind, the same token is a utility: `bg-bg-primary`, `text-text-secondary`, `border-border-light`.

```css
.surface {
  background: var(--bg-primary);
  color: var(--text-primary);
  border: 1px solid var(--border-light);
}
```

Switching between light and dark is handled at the `:root` level. Components use the same variable name in both modes.
