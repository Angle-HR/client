# Button

Use a button when someone needs to do something: save a form, confirm a choice, move on. The label says what happens, like "Save changes", never "Click here".

<Example name="button/overview" />

```tsx
import { Button } from '@/components/ui/button'
```

## Which button?

There are five buttons, all in `@/components/ui/button`.

| Component                                     | Use it for                                   |
| --------------------------------------------- | -------------------------------------------- |
| Button                                        | Most actions: save, confirm, create, cancel  |
| [Icon Button](/docs/components/icon-button)   | Icon-only actions in toolbars and table rows |
| [Text Button](/docs/components/text-button)   | Links and light actions in or near body copy |
| [Flow Button](/docs/components/flow-button)   | Moving through a multi-step flow             |
| [Label Button](/docs/components/label-button) | Filter chips that switch on and off          |

Watch the icon props: Button and Flow Button use `iconPrefix` and `iconSuffix`, Text Button uses `iconLeft` and `iconRight`, and Icon Button uses `icon`.

## Anatomy

| Part      | Spec                                                                       |
| --------- | -------------------------------------------------------------------------- |
| Container | 24px (`sm`) or 32px (`md`) high, 1px border, 7px radius                    |
| Spacing   | 8px from the outer edge, 4px between icon and label                        |
| Label     | Inter Medium, 13px                                                         |
| Icons     | Optional, 14×14px, before (`iconPrefix`) or after (`iconSuffix`) the label |

## Variants

`variant` sets how loud the button is; `accent` sets its colour. Any combination works.

<Example name="button/variants" />

| Variant     | Use it for                                               |
| ----------- | -------------------------------------------------------- |
| `primary`   | The one action that matters most in a view or section    |
| `secondary` | Actions beside a primary, like "Cancel" next to "Save"   |
| `tertiary`  | Quiet actions: optional steps, inline controls, toolbars |

| Accent    | Use it for                                                 |
| --------- | ---------------------------------------------------------- |
| `default` | Most actions                                               |
| `blue`    | Actions that confirm or move forward and need extra weight |
| `red`     | Actions you can't undo: delete, remove, revoke             |

## Sizes

<Example name="button/sizes" />

| Size | Height | Use it for                    |
| ---- | ------ | ----------------------------- |
| `sm` | 24px   | Tables, toolbars, filter bars |
| `md` | 32px   | Everything else (default)     |

Keep to one size within a group of buttons.

## With icons

Pass a 14px `MaskIcon` from `public/dashboard/icons`. Those files keep Figma's 16px frame, so the glyph sits in the box just as it does in Figma, and it takes the button's text colour.

```tsx
<Button iconPrefix={<MaskIcon src="/dashboard/icons/plus-outline.svg" size={14} />}>
  Invite member
</Button>
```

<Example name="button/with-icons" />

Avoid the components in `@/components/ui/icons` here. Their padding is trimmed, so at 14px the glyph fills the box and looks too big.

## Loading

Set `loading` while the action runs. A spinner replaces the left icon, the label stays, and extra clicks are ignored. Update the label to match, like "Saving…".

The button keeps focus while it loads, so keyboard users don't lose their place. Figma doesn't have this state yet.

## In context

**Forms:** make the primary `type="submit"` so Enter works. Line buttons up with the left edge of the fields, primary first.

<Example name="button/form-submit" />

**Toolbars:** use `sm`, mostly tertiary.

<Example name="button/toolbar" />

**Modals:** primary on the right, Cancel to its left. In a destructive modal, the confirm button is primary and red.

**Phones:** in a single column, buttons can fill the width with `className="w-full"`. Use `className` for layout only, never colour.

## States

<ButtonStates />

Hover fades in over 100ms with Figma's ease-in curve and out over 100ms with its ease-out curve. A press takes 50ms. Focus and disabled change instantly, as in the Figma prototype.

## Usage

<DoDont>
  <Guideline kind="do">Use one primary per area, for the action that matters most.</Guideline>
  <Guideline kind="dont">Put two primaries side by side. Neither stands out.</Guideline>
  <Guideline kind="do">Use red for actions that can't be undone.</Guideline>
  <Guideline kind="dont">
    Use red for anything reversible. It worries people for no reason.
  </Guideline>
  <Guideline kind="do">Show `loading` so people know their click landed.</Guideline>
  <Guideline kind="dont">Quietly disable the button after a click.</Guideline>
</DoDont>

## Writing labels

- Start with a verb: "Save", "Invite", "Export".
- Be specific: "Save changes" beats "Save".
- Sentence case, one to three words, no full stop.
- While loading, say what's happening: "Saving…".

## Accessibility

- **Keyboard:** Tab to reach it, Space or Enter to press it.
- **Focus:** as in Figma. Default buttons get a blue 1px border. Blue and red buttons swap their border for a 1px ring just outside the edge (blue on red buttons and on blue tertiary; on blue primary it matches the fill). Blue secondary gets a blue border.
- **Disabled:** `disabled` removes it from the tab order. To keep it focusable so you can explain why, use `aria-disabled="true"` and block the click.
- **Loading:** sets `aria-busy` and `aria-disabled` and keeps focus. Change the label so screen readers hear it.
- **Colour:** red alone doesn't mean "danger". The label has to say it.
