# Text area

Several lines of text, with an optional label, helper text, formatting toolbar and action button.

<Example name="text-area/overview" />

```tsx
import { Textarea, TextareaField } from '@/components/ui/textarea'
```

`Textarea` is the labelled field most forms use. `TextareaField` is the bare field, for places that bring their own label.

## Layout

| Part          | Value                                                                                |
| ------------- | ------------------------------------------------------------------------------------ |
| Field         | 12px padding and a 12px gap (the 1px border sits inside), 8px corners                |
| Height        | Grows with the text from 80px to 500px, then scrolls                                 |
| Text          | 13px, Body S, 19.5px lines; 4px above the first line's capitals, 12px below the last |
| Toolbar       | Five 20px buttons edge to edge, 12px icons                                           |
| Action button | 24px, Tertiary, Blue; 10px from the top and right                                    |
| Scrollbar     | Figma's scrollbar over the field's right edge, full height                           |

Below the `md` breakpoint the text is 16px, so iOS Safari doesn't zoom in (not in Figma).

## States

<TextAreaStates />

- **Placeholder** (empty): grey placeholder text.
- **Hover**: a darker border, only while the field is empty. Fades in over 100ms, ease in.
- **Focus**: a blue border. 100ms, ease out.
- **Selected**: focus, with selected text on a light blue (22%, 17% in dark).
- **Filled**: once there is text, a slightly darker border.
- **Error** (`errorText` or `aria-invalid`): a pink border, red helper text.
- **Disabled**: a grey fill and text at 20%. The field itself isn't faded, and the toolbar keeps its colours.

## Parts

### Toolbar

<Example name="text-area/toolbar" />

| Button        | Icon (solid, 12px) |
| ------------- | ------------------ |
| Bold          | `bold`             |
| Italic        | `italic`           |
| Underline     | `underline`        |
| Bulleted list | `list-bullet`      |
| Numbered list | `numbered-list`    |

Each button is 20px with 4px padding and no fill. The icon is `text/input/icon-rest` (#333, #ebebeb dark) and turns `text/input/icon-hover` (blue, #849dff dark) on hover and while pressed. Figma has no motion on them.

The toolbar is on by default on `TextareaField` and off on `Textarea`, as in Figma. With it on, the field becomes a rich-text editor: the buttons bold, italicise, underline and make lists, and each one shows as selected while the cursor is in that format. The value is then HTML, so read it with `onValueChange`. Pasted text comes in plain. Without the toolbar the field is a plain `<textarea>`.

### Drag to resize

A handle in the bottom-right corner drags the field taller, never under 80px, and past the 500px cap. Double-click it to put the height back. It's hidden when the field is disabled or read-only. Not in Figma.

### Action button

<Example name="text-area/action" />

Figma's ✨ show-sec_actions: one button 10px from the top right. `Textarea` draws it from `actionButtonLabel` and `onAction`; `TextareaField` takes any node as `action`.

With the toolbar, the button sits at the end of the toolbar's row. Without it, Figma lays the button over the text, which hides the end of the first line; here it gets a row of its own and the text starts below it (not in Figma).

### Label and helper

The label is the shared `LabelWrapper` (12px, weight 550, `text/tertiary`, inset 3px). The helper text is 12px in `text/light`, or `text/Error` with an error, and, unlike the text input's, it isn't inset (Figma's Helper-Text with Padding = no). Label, field and helper sit 6px apart.

**Figma oddities, copied as they are or noted:**

- The labelled Text Area turns the toolbar off; the field alone has it on.
- Figma's toolbar always shows Underline in its blue Hover/Selected look, even when disabled. Here it's blue only while pressed.
- Disabled keeps the toolbar icons at their rest colour.
- The prototype goes Focus → Filled on click and back on mouse leave; here the field follows real focus.
- The scrollbar is switched off in every Figma variant; here it shows whenever the text overflows.

**Not in Figma, kept in code:**

- Real formatting from the toolbar (an HTML value), and the pressed state of its buttons.
- The drag-to-resize handle.
- The action button's own row when there's no toolbar.
- Keyboard focus on a toolbar button: the selection controls' 1px blue ring.
- The 16px text on small screens.
- `readOnly` and `maxLength`.

## Accessibility

- `Textarea` names the field from its label (`aria-labelledby`, which also covers the rich editor), and links its helper or error with `aria-describedby`.
- The rich editor is a multi-line `textbox` with the usual shortcuts (⌘B, ⌘I, ⌘U).
- Dragging is never needed: the field scrolls, so all the text can be reached without the handle (WCAG 2.5.7).
- Errors set `aria-invalid` and are announced as they appear; `required` sets `aria-required` and adds the asterisk.
- The toolbar is a group named "Formatting"; each button is named and says whether it's pressed.
- In a disabled field the toolbar buttons leave the Tab order.
