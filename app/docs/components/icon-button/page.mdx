# Icon Button

A square button with just an icon. Use it where space is tight and the icon is obvious: close, search, edit, delete. If people might have to guess, use a [Button](/docs/components/button) with a label.

<Example name="icon-button/overview" />

```tsx
import { IconButton } from '@/components/ui/button'
```

There's no visible label, so `aria-label` is required.

## Variants

<Example name="icon-button/variants" />

| Variant         | Use it for                                                       |
| --------------- | ---------------------------------------------------------------- |
| `primary`       | The main icon action in a view                                   |
| `secondary`     | Icon actions beside a primary, or secondary toolbar controls     |
| `tertiary`      | Quiet actions in table rows and dense layouts                    |
| `light`         | The quietest: a light grey icon that never gets a fill           |
| `light-w-hover` | Like `light`, with a faint fill on hover so it reads as a target |
| `error`         | Destructive actions like delete. Red icon, light red on hover    |

## Sizes

<Example name="icon-button/sizes" />

| Size | Box     | Icon | Radius | Use it for                                 |
| ---- | ------- | ---- | ------ | ------------------------------------------ |
| `xs` | 16×16px | 10px | 4px    | Tiny inline controls, like removing a chip |
| `sm` | 24×24px | 14px | 7px    | Toolbars and table rows                    |
| `md` | 32×32px | 14px | 7px    | Everything else (default)                  |

The icon is centred, with 5px of padding at `xs` and `sm`. Pass it as a `MaskIcon` at the icon size, as on the [Button page](/docs/components/button#with-icons). Primary, secondary and tertiary icons are mid grey; `light` is lighter; `error` is red.

`light-w-hover` at `sm` is 6px round, not 7px, as in Figma. Its fill only shows on hover and press.

Keep to one size within a toolbar. `xs` is far too small to tap, so keep it to desktop-only extras.

## Counter badge

A small blue badge over the top-left corner, for a count tied to the action. It shows `99+` past 99 and hides at 0. Put the count in the `aria-label` too.

## Tooltip

Figma's Icon Button has a tooltip option: a small dark label above the button. It isn't built in code yet, so there's no `tooltip` prop. Until it is, use `title` for a plain browser tooltip.

## States

<IconButtonStates />

Hover fades in over 100ms with Figma's ease-in curve and out over 100ms with its ease-out curve; a press takes 50ms. `light` doesn't change on hover or press.

Focus is a blue border on a white fill, as in Figma. Figma has no focus state for `light` or `light-w-hover`, so they show no focus style. Only use them next to something else that shows where focus is.

## Usage

<DoDont>
  <Guideline kind="do">Use icons everyone knows: close, search, add, filter, settings.</Guideline>
  <Guideline kind="dont">Use an icon that could mean two things. Add a label instead.</Guideline>
  <Guideline kind="do">Name the action in `aria-label`, verb first: "Close dialog".</Guideline>
  <Guideline kind="dont">Describe the picture: "Magnifying glass".</Guideline>
  <Guideline kind="do">Add a tooltip in toolbars that matches the `aria-label`.</Guideline>
  <Guideline kind="dont">Delete straight away from an `error` button. Confirm first.</Guideline>
</DoDont>

## In context

- **Toolbar:** `sm`, 8px apart. Past five or six, add a separator.
- **Table row:** `tertiary` at `sm`. Show row actions on hover where you can.
- **Phones:** the button can look 24px, but the tap target needs to be 44px. Pad the parent rather than stretching the button.

## Accessibility

- **Name:** `aria-label` is required, and TypeScript checks it.
- **Keyboard:** Tab to reach it, Space or Enter to press it.
- **Focus:** a blue border, as in Figma. `light` and `light-w-hover` have no focus style in Figma, so keyboard users can't see them focused. Prefer `tertiary` where keyboard use matters.
- **Changing counts:** a new `aria-label` isn't announced on its own. Add a hidden `aria-live="polite"` region.
- **Disabled:** to keep it focusable so a tooltip can explain why, use `aria-disabled="true"` and block the click.
